gstack: Garry Tan's Claude Code setup

Garry Tan, President and CEO of Y Combinator, open-sourced the setup he builds with every day. It turns Claude Code into a small team: 23 specialists and 8 power tools, all slash commands, all Markdown, free under MIT.

GitHub: garrytan/gstack133,954 stars on Sep 23 2026About 30 seconds to installMIT

Repo: github.com/garrytan/gstack

What you get

Instead of a blank prompt, every stage of a sprint has its own command, and each one hands its output to the next: Think, Plan, Build, Review, Test, Ship, Reflect. The four you will use first:

/office-hoursStart here. Six forcing questions that reframe your product before any code is written, then a design doc the later skills read.
/reviewA staff-engineer review of your branch: the bugs that pass CI but blow up in production. Fixes the obvious ones, asks about the rest.
/qaOpens a real browser on your app, clicks through the flows, fixes what it finds and writes a regression test for each fix.
/shipSyncs main, runs the tests, audits coverage, pushes and opens the PR.

The rest cover planning (/plan-ceo-review, /plan-eng-review, /autoplan), design (/design-review, /design-shotgun, /design-html), debugging (/investigate), security (/cso), deploys (/land-and-deploy, /canary) and safety rails (/careful, /freeze, /guard).

1Check the requirements

  • Claude Code and Git
  • Bun v1.0 or newer
  • On Windows also Node.js

2Install (paste into Claude Code)

Open Claude Code and paste this sentence. Claude clones the repo into your skills folder, runs the setup and adds a short gstack section to your CLAUDE.md:

Install gstack: run git clone --single-branch --depth 1 https://github.com/garrytan/gstack.git ~/.claude/skills/gstack && cd ~/.claude/skills/gstack && ./setup then add a "gstack" section to CLAUDE.md that lists the available gstack skills.

The README has the full version of that sentence, including the exact skill list. If you prefer the shell, the first half is all it runs:

git clone --single-branch --depth 1 https://github.com/garrytan/gstack.git ~/.claude/skills/gstack
cd ~/.claude/skills/gstack && ./setup
Know what setup changes: besides the skills it registers hooks in ~/.claude/settings.json, among them a Stop hook (gstack-timeline-stop) that closes interrupted session timelines. Opt out with ./setup --no-timeline-stop-hook. Read the README before running it on a work machine.

3Run the first five commands

This is the author's own quick start, in order:

  • /office-hours and describe what you are building
  • /plan-ceo-review on any feature idea
  • /review on any branch with changes
  • /qa on your staging URL
  • Stop there. You will know whether it is for you.

4Optional: share it with your team

From inside a repo, team mode makes teammates' Claude Code pick up gstack automatically and commits the change:

(cd ~/.claude/skills/gstack && ./setup --team) && ~/.claude/skills/gstack/bin/gstack-team-init required && git add .claude/ CLAUDE.md && git commit -m "require gstack for AI-assisted work"

Swap required for optional to nudge instead of block.

Removing it again

~/.claude/skills/gstack/bin/gstack-uninstall

That removes the skills, global state and its hooks. It does not edit CLAUDE.md: delete the ## gstack section there yourself.

Honest notes

  • It is opinionated. The commands follow one person's sprint. If you only want a code reviewer, /review alone is fine.
  • Some skills want extra tools: the browser skills build their own Chromium on setup, /cso needs a native C toolchain, and a few features (like the Memorable bridge) are not available on Windows yet.
  • It also runs in Codex, Cursor, OpenCode and other agents via ./setup --host <name>, but this guide is about Claude Code.
