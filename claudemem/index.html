claude-mem: Claude Code remembers yesterday

Every Claude Code session starts from zero. claude-mem watches what Claude does, compresses it into short observations, stores them in a local database and puts the relevant ones back into your next session. You stop re-explaining your project every morning.

How it works

5 lifecycle hooksSessionStart, UserPromptSubmit, PostToolUse, Stop and SessionEnd. They see every prompt and tool call without you doing anything.
SQLite + ChromaSessions, observations and summaries go into a local SQLite database, with a vector index for semantic search on top.
Context injectionWhen a new session starts, the relevant observations from earlier sessions are already there.
mem-searchAsk in plain language ("how did we fix the auth bug?") and Claude searches your project history.

1Check the requirements

  • Claude Code, a current version with plugin support
  • Node.js 20 or newer (on Windows: if npm is "not recognized", install Node.js and restart the terminal)
  • Bun and uv are installed automatically if they are missing

2Install

Option A, the installer. Run this in your terminal (PowerShell on Windows):

npx claude-mem install

After setup it opens your browser to sign in to claude-mem. That unlocks their hosted "observer", which compresses your memories off your Claude plan, free for the first 30 days. After the trial, memory falls back to your Anthropic plan unless you subscribe.

No account, nothing leaves your machine except your normal Claude usage: choose the Anthropic-plan provider right away. It skips cmem.ai completely and asks which Claude model should compress the observations.

npx claude-mem install --provider claude

Option B, from inside Claude Code. Two native plugin commands:

/plugin marketplace add thedotmack/claude-mem
/plugin install claude-mem

Then restart Claude Code.

Not npm install -g claude-mem. That installs only the library: no hooks, no worker, no memory. Always use npx claude-mem install or the /plugin commands.

3Just work

Use Claude Code like always. The hooks record in the background. The worker prints a local URL on startup: open it to watch the memory stream live in the web viewer.

4Open a new session

Start Claude Code again tomorrow. Context from previous sessions shows up on its own. To dig deeper, ask Claude to search your memory. Under the hood it uses three MCP tools in a row, which saves about 10x tokens compared with loading everything:

searchA compact index of matching observations with IDs, about 50 to 100 tokens per result.
timelineWhat happened around one observation, in order.
get_observationsThe full details, only for the IDs you actually need.

Privacy

  • Wrap anything sensitive in <private> tags and it is not stored.
  • Settings live in ~/.claude-mem/settings.json (model, port, data directory, what gets injected). It is created on the first run.

Removing it again

Plugin install: open /plugin in Claude Code and uninstall claude-mem, then restart. Your stored memories stay in ~/.claude-mem until you delete that folder yourself.

Honest notes

  • Compressing observations costs model usage. With the Anthropic-plan provider it comes out of your Claude plan.
  • It works with more than Claude Code (Codex, Gemini, OpenCode, Copilot and others), but Claude Code is the main target.
  • Open source under Apache-2.0. The hosted observer and cloud sync are optional paid extras; nothing in this guide needs them.
