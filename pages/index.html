Guide · GitHub Pages

Put a website online with Claude Code, in three steps

Free hosting on GitHub Pages, straight from the terminal. Claude Code runs the commands, you press yes.

Windows, macOS, LinuxAbout 5 minutesFree

You need Claude Code installed and a folder with at least one index.html. Don't have one? Ask Claude to build the page first, then come back here.

1Install the GitHub CLI

The GitHub CLI (gh) is the tool Claude uses to talk to GitHub. One command:

# Windows
winget install --id GitHub.cli -e

# macOS
brew install gh

# Ubuntu / Debian
sudo apt install gh

Or just tell Claude Code:

Install the GitHub CLI on this machine.

Windows: open a new terminal after the install, so gh is on your PATH.

2Log in with a one-time code

gh auth login --web

The terminal shows an eight-character code and opens github.com/login/device. Type the code, click Authorize, done. Claude never sees your password: GitHub hands the tool a token, and you can revoke it any time in your GitHub settings.

Check it worked:

gh auth status

3Create the repo, push the page, switch on Pages

Inside your site folder, tell Claude Code:

Create a public GitHub repo for this folder called my-site, push it, and switch on GitHub Pages from the main branch.

These are the commands Claude runs, if you'd rather do it by hand:

git init
git add -A
git commit -m "First version"
git branch -M main
gh repo create my-site --public --source=. --push
gh api -X POST repos/<your-username>/my-site/pages -f 'source[branch]=main' -f 'source[path]=/'

About a minute later your site is live at:

https://<your-username>.github.io/my-site/
Updating the site later: change the files, then git add -A && git commit -m "Update" && git push. Or tell Claude "push the changes". Pages rebuilds on every push.

Good to know

  • Pages serves static files only: HTML, CSS, JavaScript, images. No server code, no database.
  • The repo is public, so the source of your site is public too. Fine for a landing page, not for secrets.
  • Add a file called .nojekyll to the folder so GitHub serves your files exactly as they are.
  • Custom domain: in the repo, Settings → Pages → Custom domain, then a CNAME record at your DNS provider.
