fast-jev-compaction: compaction that never writes a summary

Every compact today hands your session a paraphrase and throws the originals away. This plugin scores each old tool call instead, deletes the stale ones, and leaves everything it keeps word for word. Two commands and one key.

The problem it fixes

Standard compaction asks a model to summarize your old turns. A summary is lossy in exactly the way that hurts: a file path, an exact error string, a constraint you stated once, the command that finally worked. All of it can quietly vanish, and you find out ten minutes later when the agent re-reads a file it already read, or edits the one you told it never to touch.

Built-in compactionRewrites your history into prose. "Worked on the users API and fixed a failing test." The TypeError, the path src/api/users.ts and your "never edit src/generated/" are gone.
fast-jev-compactionDeletes whole tool calls it judges stale. Nothing is rewritten. What survives is the original text, in the original order, character for character.

1Turn on function hooks

The plugin runs as a Claude Code function hook, which is early access from 2.1.274 on, so the flag has to be set wherever Claude Code runs. In ~/.claude/settings.json:

{ "env": { "CLAUDE_CODE_ENABLE_FUNCTION_HOOKS": "1", "TYPESAFE_API_KEY": "<your key>" } }
On the key: the scoring pass runs against Jev through the TypeSafe API, so it needs TYPESAFE_API_KEY. Keep it in your environment or a password manager. Never put it in a source file and never commit it.

2Install the plugin (two commands)

From the shell, or as slash commands inside a session:

claude plugin marketplace add tamaratran/fast-jev-compaction
claude plugin install fast-jev-compaction@fast-jev-compaction

The install asks for the options (API key, thresholds, truncateHeadChars). Leave them at their defaults and it picks up TYPESAFE_API_KEY from the environment. Then restart Claude Code or run /reload-plugins.

3Read the toast

From then on /compact and auto-compaction go through the plugin, and the toast tells you which path it took:

fast-jev-compaction: kept N/M messages, no summaryIt worked. The pruned original history replaced the built-in summary.
fallback to built-in summaryJev could not remove enough to be worth it, or the call failed. You get normal compaction, nothing breaks.

How the scoring works

  • Every tool_use is paired with its tool_result. Calls in the first message and in the newest preserveRecentMessages (6 by default) are pinned and never touched.
  • Jev sees the whole conversation, oldest first, with tool results replaced by a short note like ok, 4213 chars (omitted). Nothing it judges has been summarized first.
  • For each non-pinned call it answers two questions: should the call stay, and should the result stay verbatim.
  • Against keepThreshold (0.5) that gives three outcomes: keep both, or keep the call and truncate the result to its first 300 characters plus a one-line note, or drop the call together with its result.
  • A result is never left without its call, and untouched messages come back as the exact same objects.

The honest limitations

  • Only tool calls and results are candidates. Your text and the assistant's text are never removed or shortened in the output.
  • Token sizes are estimated from character counts, not a tokenizer.
  • A keep probability is not a proof that deleting a result is safe. The upside: the agent can always re-run a tool, which it cannot do with a summary.
  • The full state is resent with every request, so a very long history costs one request per handful of questions.

Also an npm library

The same repo is a package, if you want this inside your own harness rather than in Claude Code:

npm install fast-jev-compaction
export TYPESAFE_API_KEY=...

Call compactMessages(transcript, { preserveRecentMessages: 4 }) and check reductionRatio(result) before you commit to it. Message is a subset of Claude Code's SessionMessage, so a session transcript goes in as is.
